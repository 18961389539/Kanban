## 0. 本次范围

**包含**
- 新维度数据 = 同一台 PLC 上可通过寄存器读取的数据（温湿度/能耗等）
- 两种采集方式：定时触发（遵循现有轮询设置，无独立周期配置）与 PLC 电平触发（D100==1 → 采集 → 回执）
- 执行模式仅 **Inline**（监视 + 采集 + 回执同轮完成）

**明确不包含**
- 外部事件触发（RFID / 计数 / 消息队列）、外部 API / 串口仪器 / AGV 系统（Queued 不做）
- 独立采集周期配置、独立线程/进程
- 车间级/全局源（所有数据源必须挂设备）

## 1. 配置模型：数据源是 device 的属性

数据源**内嵌于 devices.json 的设备对象**。所有数据源必须归属某台设备，无全局源。

```
devices.json
└── devices[] → 每个设备对象内新增 "sources": [ ... ]
```

- 采集参数（地址映射、触发、阈值）全部位于设备上下文，一处管理
- 数据源复用现有地址映射格式；加载/校验/损坏备份沿用现有配置机制
- 数据源**不参与设备状态机**：越限/偏离走普通报警，不驱动设备离线/停产，不污染 OEE
- **管理入口**：不做设置页 UI，并入**设备管理**（设备详情中编辑其 sources），与"数据源是设备属性"的模型自洽

## 2. sources 配置项清单

| 项 | 必填 | 说明 |
|---|---|---|
| 名称 / 类型 | 是 | 温湿度 / 电表 等，标识与展示 |
| 地址映射 | 是 | 采集寄存器静态地址集合（复用现有映射格式） |
| 触发地址 | 否 | 有则电平触发；无则每轮采集（定时） |
| 触发值 / 回执值 | 否 | 默认 1 / 2，回执写同一地址 |
| 单位 / 枚举表 | 否 | 数值型单位；非数值型取值含义（0=就绪 1=运行 2=报警） |
| 数值型：上下限 | 否 | `min / max` + 滞回 `hysteresis` |
| 数值型：延时确认 | 否 | 越限持续 N 秒才确认报警，默认 5s（面板可调），防瞬时尖峰误报 |
| 非数值型：预期值 | 否 | 当前值 ≠ 预期值 → 偏离报警 |

## 3. 触发语义（定稿）

- **唯一拓扑：回执地址 = 触发地址**；**无沿检测**，以"当前值 == 触发值"判定
- 每轮：读触发地址 → 值==触发值 → 采集 → 同址写回执值 → 下轮不再触发，等 PLC 再次置 1
- 未配置触发地址 = 每轮无条件采集（定时，周期=扫描周期）
- 断线重连后按当前值直接判定，不追溯历史命令
- **协议约定**（写入设备手册，非代码逻辑）：PLC 端遵守「置 1 → 等回执码 → 再置 1」节奏

## 4. 判定与告警动作（定稿）

告警是**状态机**，不是每轮判读即报：`正常 → 越限/偏离（触发告警）→ 恢复（解除告警）`，进入/恢复各记一次，不刷屏。

- **数值型**：越过 min/max 且持续超过延时确认时间 → 越限告警；回落到「限值 ∓ hysteresis」内才恢复
- **非数值型**：当前值 ≠ 预期值 → 偏离告警；回到预期值 → 恢复（离散量不做延时，可留配置位）
- **动作分级（定稿：暂用两级）**：越限/偏离 → 进 `alarm_events` + 声音提示（沿用现有声音开关）；恢复 → 解除并记录，不触发声音。暂不设第三级
- **来源区分**：数据源告警与 PLC 设备报警在报警中心可区分（来源类型字段）——一个是 PLC 自报故障，一个是我们算出的越限，便于排查
- 统一复用现有报警中心（展示、声音开关），不引入第二套通知

## 5. 快照与历史存储（定稿）

- **单张快照表 + device_id 字段 + 索引**，查询按设备聚合（聚合是查询维度，不做每设备物理分表）
- 字段：`device_id / source 名与类型 / 时间戳(UTC) / 值（数值型 REAL，非数值型枚举码）/ 单位 / 有效性标记`
- 保留策略跟随现有历史库体系；落盘仍走现有历史节拍

## 6. 校验规则（设备校验内新增）

- `max > min`；滞回与延时确认取值合法；预期值在枚举表内
- 触发地址不与采集地址重叠
- 仅当该设备 `sources` 非空时触发，沿用现有配置校验报错体系
