用户管理页（UserManagerView）UI 改进

现状：左 DataGrid（用户名/显示名/角色/启用/最后登录）+ 右列固定 300px 双面板堆叠（编辑选中用户 / 添加新用户）。以下 5 个方案为独立预览，可组合落地。
1

右侧操作区 Tab 化：编辑 / 添加合并，宽度随列表自适应

易实现收益高

问题：右列固定 300px，编辑面板（选中用户时）与添加面板竖向堆叠，添加面板始终占位；选人后列表宽度不变，小屏下编辑区被挤压；两面板风格割裂。

方案：右侧单卡片 + 顶部 Tab 切换（"编辑选中用户" / "添加新用户"）；选中用户时自动切到编辑 Tab，未选中显示添加 Tab；列宽改为可拖拽（GridSplitter，与配方页一致），列表默认 2:3。

2

列表升级：搜索 + 角色筛选 + 角色徽章 + 行内快捷操作

中等收益高

问题：无搜索/筛选（账号多了靠肉眼找）；角色是纯文本；重置密码/删除必须先进右侧面板，两步操作。

方案：列表头部加搜索框（用户名/显示名模糊）+ 角色筛选胶囊（全部/管理员/工程师/操作员，带计数）；角色改彩色徽章（Admin 主色/Engineer 绿/Operator 灰）；行尾快捷图标（重置密码钥匙、删除垃圾桶，悬停显示）。

3

密码策略：强度条 + 确认输入 + 首次改密提示

中等收益高

问题：当前只查"非空"，密码 "1" 也能过；重置密码无确认输入，输错即改不可撤销；默认账号（admin/gly）从未被强制改密。

方案：密码字段加实时强度条（长度 + 字符类型 → 弱/中/强，颜色红/黄/绿）；新增"确认密码"字段（不一致红字提示，添加与重置两处统一）；首次登录必须改密标记（服务端 flag，登录后弹改密对话框）。

4

登录安全：失败锁定 + 状态徽章 + 解锁操作

较大中收益

问题：登录无失败次数限制（可暴力尝试）；账号状态只有"启用/禁用"两态，无锁定概念；审计有记录但界面上看不到异常登录。

方案：连续失败 5 次锁定 10 分钟（FailedAttempts + LockedUntil 持久化到 users.json）；列表状态徽章扩展为 启用/禁用/锁定（黄）；管理员可"解锁"（一键清零计数）；锁定账号登录时提示剩余时间。

5

安全体检横幅：默认口令 / 免密 / 从未登录风险一目了然

易实现低频

问题：默认账号口令写死（admin/gly、engineer/gcs）、operator 免密、从未登录的账号——管理员不逐条点开根本不知道；无强制改密机制。

方案：页面顶部"安全提醒"横幅（黄=提示/红=风险）：列出 默认口令未改 / 免密账号 / 从未登录（超 30 天）三类，点击定位到对应账号并预置"重置密码"；列表行加风险角标；新账号落库时可选"首次登录必须改密"。

落地建议

阶段方案理由
第 1 批（快赢）① 右侧 Tab 化 　② 搜索/筛选/徽章/快捷操作纯前端、零数据模型改动，直接改善日常操作效率
第 2 批③ 密码策略 + 确认 　⑤ 安全体检横幅安全底线，改 UserStore 校验 + 只读风险计算，无迁移
第 3 批④ 登录失败锁定需要 users.json 字段迁移与登录流程分支，收益场景取决于部署
