看板 UI 改进建议

基于设计系统（Brushes / Cards / Components / FontSizes）与 8 个主要视图的实读分析 · 2026-07-27
基线评价：设计系统已相当成熟。 全项目颜色走 Brushes 资源（零硬编码 hex）、空状态 EmptyState 组件覆盖广、AutomationProperties.Name 命名普遍、MainWindow 已用 Viewbox 做屏幕等比缩放、卡片/状态色/药丸/色条体系完整。

因此本报告的改进点集中在 「已建好的样式未统一落地」 与 「少数破坏既有能力的硬编码」，而非推倒重来。

P0 · 影响已有功能正确性的核心问题

P0①「界面字号」全局缩放对大量文本失效

设置页提供 界面字号（标准100% / 大屏115% / 超大屏130%），由 FontSizeManager.ApplyScale 在启动时与设置切换时覆盖 FontSizes.xaml 的语义键（FontSizeHero/FontSizeKpiLg…）。但许多 TextBlock 直接硬编码了 FontSize，这些控件会绕过缩放。

  • 证据： HomeView.xaml:37/45/66/137（时钟 24、刷新时间 13、PLC 状态 13、断线横幅 14）、AlarmCenterView.xaml:156/183/242（KPI 值 16、计数徽章 12、列表 14）、以及 ProductionLineView / DeviceManagerView / HistoryQueryView 的洞察文本约共 40+ 处硬编码。
  • 影响： MainWindow 已用 Viewbox 做屏幕等比缩放，所以 屏幕适配没问题；但用户的「字号偏好」缩放对硬编码控件静默失效——切换 130% 后部分文字不变，视觉不统一。
  • 修复： 把硬编码 FontSize 改为 {DynamicResource FontSizeXxx}；若语义键不够，在 FontSizes.xaml 增键（如 FontSizeKpiValue）。AlarmCenterView:156 连 KpiValue 样式都覆盖了，优先改这里。
定位： grep FontSize="[0-9] in MainAPP/Views → 6 文件命中；grep FontSize="{DynamicResource FontSize → 13 文件已正确引用。混合使用正是根因。

P0② 加载 / 骨架 / 过渡态未统一覆盖

项目已建好 LoadingOverlay（半透明遮罩 + LoadingCircle）、SkeletonBorder（脉动骨架）、PageTransition（0.2s 淡入）三套样式，但只被 3 个页面使用。

  • 证据： grep "LoadingOverlay|hc:LoadingCircle|SkeletonBorder|PageTransition" MainAPP/Views → 仅 HistoryQueryView / DeviceManagerView / OverviewView。首页（大屏门面）、产线、设置、报警中心均无页面级加载指示与淡入。
  • 影响： 实时数据首屏、报警中心拉取时，用户看到的是突兀的空状态跳变或瞬切，缺少"正在加载"的过渡，大屏观感粗糙。
  • 修复： 在 Home / ProductionLine / Settings / AlarmCenter 套用已就绪样式：内容区加 LoadingOverlay 绑定 IsLoading，首屏用 SkeletonBorder 占位，页面根加 Style={StaticResource PageTransition}。

P1 · 可维护性 / 自适应 / 体验一致性

P1③ 首页顶部栏缺乏自适应（窄宽碰撞）

HomeView 顶部把左集群（标题/时钟/刷新/PLC状态）与右集群（设备 ComboBox 260px / 班次进度条）并列于同一 Grid 单元，靠 HorizontalAlignment 左右贴边，无 WrapPanel、无溢出处理。

  • 影响： 设计宽 1712px 下 OK；但若 Viewbox 失活或窗口被压窄，右集群会压到左集群文字上。建议改用 WrapPanel 或把顶部拆成可换行的两行布局。

P1④ 历史查询 Tab 头缺自动化名（呼应前次问诊）

项目已有完整 UIA 测试体系（如 DeviceManagerFlowTests），多数页面给交互元素加了 AutomationProperties.Name。但 HistoryQueryView 的 4 个 Tab 头（图标+文字 StackPanel）没有，无法被 UIA 树识别/键盘定位。

  • 修复： 给每个 TabItem.Header 根元素加 AutomationProperties.Name="产量查询 标签" 等。

P1⑤ 滚动虚拟化（CanContentScroll）用法不一致

ScrollViewer 在报警中心、实时故障卡、设备参数 Tab 用了 CanContentScroll="True"（开启虚拟化），但 HistoryQuery / ProductionLine / 设置页未设。长列表（报警流）下滚动平滑度与内存不一致。

  • 修复： 统一规则：虚拟化的列表型内容（报警、设备）用 CanContentScroll="True" + 虚拟面板；纯文档型内容保持默认。

P2 · 打磨细节

P2⑥ 冗余的 PLC 状态文本

HomeView:68 的 PLC 状态 TextBlock 同时写了内联 Text="PLC 未连接" 与 Style setter 里的默认值，后者又由 DataTrigger 翻成"已连接"。内联值被样式覆盖，属多余且易误导。

P2⑦ 报警中心徽章内联 Foreground/背景略偏离资源

AlarmCenterView:182-184 活跃计数徽章用内联 Foreground="White" + DangerBrush。对比度没问题，但未走统一徽章资源，后续主题微调时易漏。

P2⑧ KPI 数字未统一等宽，实时跳动

时钟用了 FontFamily="Consolas"（HomeView:38），但 KPI 数值（产量/OEE/良率）未统一等宽字体，实时刷新时数字宽度抖动、右对齐列跳动。建议 KPI 数值统一 Consolas/TabularFigures。

✅ 已做得好的地方（保持即可）
  • 颜色系统零硬编码 hex： grep 全 Views 无 Background/Foreground/Fill="#xxxxxx"，全部走 Brushes 资源——主题切换/对比度管控有统一抓手。
  • 空状态组件化： controls:EmptyState 在首页各卡、设备管理、报警中心、概览、历史查询广泛落地，体验一致。
  • 可访问性命名普遍： 侧边栏、筛选器、设备管理等大量交互元素已加 AutomationProperties.Name，支撑 UIA 自动化测试。
  • 屏幕自适应： MainWindow 用 Viewbox Stretch="Uniform" 等比缩放 1920×1080 设计画布，天然适配不同大屏分辨率。
  • 设计令牌完整： 状态语义色（运行绿/报警红/暂停黄/待机灰）、Soft 背景、药丸徽章、状态色条、图表标题条、卡片层级齐全。
