> 面向第一次使用 Kanban 工业看板的操作员、班组长和现场管理员。

## 1. 这套系统能做什么

Kanban 用来集中查看和管理生产现场信息：

- 查看设备当前状态：运行、待机、报警、离线或未知。没有时长数据时，环形图显示「暂无状态数据」。
- 查看总产量、良品数、不良数、生产速度和 OEE 指标。
- 查看实时报警、报警发生记录和恢复记录。
- 查询生产、状态转换和报警历史。
- 管理设备、PLC 地址、报警点、缺陷点和计数报警。
- 创建和跟踪生产工单。
- 查看 PLC 连接、采集周期、历史存储和电脑资源状态。
- 管理授权、班次、刷新频率和界面显示设置。

## 2. 第一次使用前

### 2.1 使用前检查清单

第一次启动前，请让设备管理员确认：

- 电脑已经连接到 PLC 所在的网络。
- 已知 PLC 的 IP 地址和端口。
- 已准备好设备名称和各个 PLC 地址。
- 已确认当前班次的开始时间和结束时间。
- 已确认登录账号（程序默认以管理员账号自动登录，一般无需额外操作）。
- 已完成授权或仍在试用期内。

> 不要在没有确认地址的情况下填写或点击“复位产量”。写入 PLC 的命令可能影响现场生产。

### 2.2 启动程序

1. 双击 `MainAPP.exe`，或使用管理员提供的桌面快捷方式。
2. 等待主窗口出现。
3. 如果出现授权窗口，按照“授权管理”章节处理。
4. 首次启动建议先打开“系统设置”，确认 PLC 和班次信息，再进入设备管理。

程序启动后窗口会最大化显示。如果显示器比例不是 16:9，画面可能在左右或上下留出空白，这是为了保证内容不被裁切。

程序有两种运行模式：**完整模式**（默认，所有页面可用）和**展示模式**（通常用于车间大屏，只保留主页、产线、报警等展示页面，管理入口隐藏）。切换运行模式由管理员在“系统设置 → 通用设置”中完成，详见 [12.7 运行模式（通用设置）](#127-运行模式通用设置)。

### 2.3 打开使用手册

随时需要查操作步骤时：

1. 看左侧导航栏**最底部**，点击 **「使用手册 (F1)」**。
2. 或直接按键盘 **F1**。
3. 手册会在程序内打开，含截图说明（需已生成并随程序发布截图文件）。
4. 界面语言为英文时，自动打开英文手册；其他语言暂显示中文或英文手册。

首次启动时，系统也可能弹出**快速引导**窗口，最后一步同样可点「打开使用手册」。

> 其他常用快捷键：`Ctrl+1`～`Ctrl+9` 快速切换主页、产线总览、报警中心、设备管理、工单管理、历史查询、生产复盘、系统设置、运行监控；`Ctrl+L` 切换用户；`F11` 切换全屏。

### 3.2 怎么判断连接是否正常

页面**顶部**会显示全局连接状态横幅（连接正常时横幅不显示）：

- **红色横幅**：PLC 未连接或最近连接失败，需要检查网络和设置。
- **黄色横幅（连接中）**：系统正在尝试建立连接，稍等片刻。
- **黄色横幅（数据停滞）**：连接正常但数据长时间没有更新，可能是采集端卡死。

如果 PLC 未连接，首页上的设备状态和产量不会继续更新。先查看“系统设置”和“运行监控”，不要反复点击复位命令。

> 如果系统配置为“采集服务（Remote）”数据来源，横幅反映的是**与采集服务的连接**，而非直接与 PLC 的连接；此时 PLC 是否正常请在“运行监控”中查看。

## 4. 日常开机操作

每天开机建议按下面顺序进行：

1. 打开程序，等待页面加载完成。
2. 看页面顶部，确认没有红色或黄色的连接横幅。
3. 打开“运行监控”，确认采集服务正在运行。
4. 打开“报警中心”，确认没有未处理的高等级报警。
5. 返回“首页”，确认设备数量和生产指标符合现场情况。

## 5. 首页：看懂生产情况

![首页生产仪表板](screenshots/01_home.png)

<!-- page-help:home -->
这一页的标题是「生产仪表板」，只看顶栏选中的那一台设备。数字旁边的小标签标明口径：实时是此刻，当班是本班次累计，工单是这张工单的时间窗。三张卡上的数不要混着读。

### 顶栏

圆点绿色表示 PLC 已连接，红色表示未连接。圆点右边的状态字在数据正常时会藏起来。它出现时是这几种：

- 未选择设备：还没选设备，卡片上的产量和 OEE 显示「—」。
- PLC断开：本机采集连不上 PLC。这台电脑看的是远程服务时，这里写成「服务断开」。
- 无数据：已经连上，但还没有可用的运行快照。卡片上的产量和 OEE 仍是「—」。

设备下拉只切换查看对象。旁边「工单管理」去开工单或改工单，「设备详情」看这台设备的明细。地址和报警点不在首页改，去设备管理。

### 设备状态（左上）

标题旁的字是此刻状态，不是整班的总结。鼠标放上去提示「当前状态」。

- 运行：正在生产。
- 待机：暂时停下，不一定是故障。
- 报警：当前有需要处理的报警。
- 离线：后面可能带原因，例如 PLC、通讯中断、采集停止、采集空窗。
- 未知：状态字对不上以上几种。

标题右侧是当前班次名和班次进度百分比，再往右是日期和时钟。这个百分比是这一班已经走过的时间，不是产量达成。

环的上方是「当前速度」，单位件/h，旁边标着实时。算法是本班（合格 + 不良）÷ 运行小时。运行还不到 5 秒时速度按 0 显示，避免刚启动时被放得很大。右边的百分比和下面那条，是相对额定产能的达成：90% 及以上偏绿，70% 及以上偏黄，再低偏红。

环的右侧图例从上到下是运行（绿）、报警、待机、离线。每一行是时长，以及它占四项之和的百分比。环形图中心写「状态时长占比」，下面是这个总时长，旁边标着当班。没有这些时长时，环的位置显示「暂无状态数据」。

图例下面是节拍。实际周期 = 3600 ÷ 当前速度，单位秒/件；速度为 0 时显示「—」。旁边是目标周期。两者差不到 0.01 秒时显示「● 达标」；实际每件更快显示「▲ 快 …s」；更慢显示「▼ 慢 …s」，慢的时候用警示色。

### 当前生产进度（中上）

这张卡只在有进行中工单时出现数字。没有时整张卡显示「暂无进行中工单」，并提示到工单管理开始一张。空白不是产量为 0。

有工单时，顶上是工单号和产品编码。下面四格，格子上的小标签标明口径：

- 工单目标：这张工单要做多少件。
- 当班良品数：只计当前班次的合格数。
- 工单累计良品数：跟着工单走，会跨过班次，所以可以大于当班良品数。
- 工单达成率：累计良品 ÷ 工单目标。90% 及以上偏绿，70% 及以上偏黄，再低偏红。

四格下面若排了计划，会多一条进度条。填充是实际达成，中间的刻度是按时间应该走到的位置。字是「滞后计划」时偏黄，「超前计划」时偏绿，过了计划结束会写成「已超时」。当班总产量（合格加不良）不在这张卡上，在下方「当前班次良率」。当前速度也不在这张卡上，在左上的设备状态。

### 实时故障（右上）

列出的是现在还亮着的报警。标题旁的次数是活跃总数，里面有高级时次数底色变红。次数为 0 只说明此刻没有；今天早些时候发生过、已经恢复的不在这里。

- H、M、L 是高级、中级、低级的开关，只决定列表里看不看得到这一级。关掉某一级不会把标题上的次数减掉。
- 「静音」同时停本机新报警提示音和边框闪动。列表仍会更新。整个软件的声音也可以在系统设置的显示里关。
- 新出现的一条会带上与级别同色的边框。计数类报警用计数器图标，和普通报警的图标不同。
- 同一级别里，开始得更早的靠前。首页最多列出前 5 条，多出来时旁边提示「仅显示前 5 条」。要看全部或回看过程，打开左侧的报警中心。

### OEE（左下）

范围是当前班次，三项和综合值旁边都标着当班。数据还没到正常时，四个百分比都是「—」，取整到个位。没有有效运行数据时显示「暂无 OEE 数据」。大环是综合 OEE，右边三项是 A 时间稼动率、B 性能达标率、C 良品率。综合值是三项相乘，不是平均。时间稼动、性能和综合值：85% 及以上偏绿，60% 及以上偏黄，再低偏红。鼠标放在数字上可以看到代入后的算式。

- 时间稼动率 = 运行时间 ÷（运行时间 + 报警时间）。待机和离线不进分母。长时间待机、只要没有报警，这项仍可以很高。
- 性能达标率 = 实际总产量（合格 + 不良）÷（目标产能 × 运行小时）。超过额定时最高显示 100%。
- 良品率 = 合格数 ÷（合格数 + 不良数）。这一项单独用另一套颜色：95% 及以上偏绿，90% 及以上偏黄，再低偏红。黄表示还没到 95%，但已经接近。

标题右侧的设备健康分是 0 到 100 的加权分：30% 时间稼动、20% 性能、25% 良品、25% 稳定性。稳定性 = 1 − 报警时间 ÷（运行 + 报警 + 待机），不含离线。85 及以上是健康，70 及以上是良好，60 及以上是关注，再低是异常。没有运行、报警、待机时长时显示「—」。

### 当前班次良率（中下）

左边是当班总产量，合格加不良，单位件。右边是累计良率，也就是本班次到现在的合格数 ÷（合格 + 不良），不是某一个小时自己的良率。颜色同样是 95% 及以上绿、90% 及以上黄、再低红。旁边的差值相对 95%：正数是超过目标，负数是还差。没有产量时两个数都是「—」，图的位置显示「暂无产量数据」。

图的左轴是绿色柱，一根柱是那一个小时的 OK 件数。这一小时 OK 为 0 就不画柱。右轴是折线，一个小时只留一个点，点是该小时结束前的本班累计良率，画在这一小时的正中间。例如 8 点到 9 点，刻度和点都在 8:30。当前这一小时的柱和点大约每 15 秒用最新数更新，不会等到整点才画。相邻小时连成一条线；中间空过一整小时会断开，断开处有一条灰带，写着「无数据」和空了几小时。鼠标放在柱上能看到小时和 OK 件数，放在点上能看到时刻和百分比。

### 缺陷帕累托（右下）

标题写着 TOP8，旁边标着当班。副标题是「当前设备 · 本班次新增」。柱是各类不良件数，折线是从大到小的累计占比。有数据时标题下会写「缺陷合计」件数，以及这些缺陷「占 NG」的比例。超过 8 类时，其余并成「其他（N 项）」。

三种空状态不是一回事：

- 未配置缺陷项：设备管理里还没填缺陷名称和 PLC 地址。
- 当前无不良计数：地址已经配了，当前读数都是 0。
- 暂无缺陷数据：还没有可选设备。

### 数字长时间不变

首页会自己刷新。先看 PLC 圆点，再看顶栏是不是停在「无数据」或「PLC断开」，然后打开运行监控看采集是否在跑、最后成功采集时间。可以先离开这一页再回来。仍然没有数时联系管理员，不要自行删除数据库。

首页由上、下两行共 6 张卡片组成，适合快速浏览，**不要**在首页修改设备配置。上方三张卡片（设备状态、当前生产状态、实时故障）最常用，说明如下；下方一行为 **OEE、良品率和缺陷帕累托** 卡片。

### 5.1 设备状态（左侧卡片）

- 标题旁是此刻状态：运行、待机、报警、离线或未知。旁边是当前班次和时钟。
- **环形图中心**是「状态时长占比」和本班次总时长。没有时长数据时显示「暂无状态数据」。
- 环形图右侧图例：运行、报警、待机、离线的时长与占比，以及设备健康分。

状态含义（与界面文字一致）：

| 状态 | 含义 |
| --- | --- |
| **运行** | 设备正在生产 |
| **待机** | 设备暂时停止，不一定是故障 |
| **报警** | 存在需要处理的报警 |
| **离线** | 设备未在线，或采集、通讯中断 |
| **未知** | 状态字对不上以上几种 |

### 5.2 当前生产进度（中间卡片）

- **当前速度**，以及相对额定产能的进度。
- **当班良品数、工单目标、工单累计良品数、工单达成率**。
- **当班总产量和良品率**在下方「当前班次良率」卡片；**OEE** 在下方左侧卡片。

看数字前请确认顶部班次与日期。跨班次比较时不能只看一个总数。

### 5.3 实时故障（右侧卡片）

- 列出当前活跃报警，高等级报警会以红色强调。
- 可按级别筛选；可关闭新报警提示音（不影响报警记录）。
- 点击「查看全部」可进入报警中心。

### 5.4 下方一行卡片

- **OEE 卡片**：当前 OEE 及各环节占比（时间稼动、性能、良品）。
- **良品率卡片**：良品数 / 总数及良品率趋势。
- **缺陷帕累托卡片**：主要不良类型的数量分布，便于定位重点缺陷。

### 5.5 首页刷新

首页会自动刷新。如果数据明显长时间不变：

1. 看 PLC 连接是否为绿色。
2. 打开运行监控确认“采集服务运行中”。
3. 检查“最后成功采集时间”。
4. 切换到其他页面再返回首页，或等待下一轮自动刷新。
5. 仍无数据时联系设备管理员，不要自行删除数据库文件。

从首页「设备详情」或产线卡片上的「详情」进来。侧边栏没有这一项，进来之后侧边栏不会高亮。左上「返回」或按 Esc 回到刚才那一页。还没选设备时，整页写着「未选择设备」，并提示从首页或产线页去选。这一页只看这一台，地址和报警点不在这里改。F5 立刻刷新。

### 标题旁

- 设备名旁边是此刻状态。运行是绿，报警是红，待机是黄，其余用离线的灰色，文字仍是采集到的状态。再旁边是设备编号。

### 上面几张卡，口径不要混

- 合格产量、不合格产量、良品率：这一台当前会话累计。良品率 = 合格 ÷（合格 + 不合格）。
- 今日报警：从今天 0:00 起这台设备的历史触发次数，已经恢复的也算。它不是首页右上角那种「现在还亮着」的条数。
- 运行时长：这一台累计处于运行的时间。
- 设备配置：目标产能（件/小时）和配方。PLC 地址收在可展开的一栏里，只读。
- PLC 实时值里的 OK 计数、NG 计数是 PLC 上的原始计数，复位后会跳变。它们不是首页上经过换算的会话累计。
- 当前工单写出工单号、产品和进度。没有进行中的工单时写「无活跃工单」。
- 产能对比：实际产能（件/小时）=（合格 + 不合格）÷ 运行小时，运行还不到 5 秒时按 0。差距 =（实际产能 − 目标产能）÷ 目标产能，负数是没达到目标。运行应产 = 额定产能 × 运行小时，实际产量用合格加不良。报警、待机、离线不乘进去。

### 本班小时计划

每一格是当前班次里的一个小时。计划产量按额定产能、以及这一小时有多少分钟落在班次里来折算，含停机，只计 OK。上面的运行应产不含停机，还把不合格算进去，所以两处的应产对不上是正常的。

已经过去并且达到计划的格子标「达标」，绿色边；没达到标「未达标」，红色边；当前这一小时是高亮边；还没到的小时变淡。格子上方有累计 OK、应产和百分比。不在班次时段时写「当前不在班次时段」，需要先在系统设置里配好班次。

### 再往下

- 数据采集源：有配置时先看到各源的当前值。点进一张可以看趋势，再返回实时卡片。没配时这一块是空的，到设备管理的数据采集源去加。
- OEE 分解：时间稼动、性能、良品，算法和首页相同。综合值是三项相乘。
- 状态时长分布（含离线）：运行、报警、待机、离线都进这张分布。时间稼动率的分母仍然只有运行加报警，待机和离线不进分母。
- 实时活跃报警是现在还亮着的。最近报警事件看近 24 小时，含已经恢复的。缺陷占比是这一台各类不良的构成。

## 6. 产线总览：查看整条线

![产线总览](screenshots/02_production_line.png)

<!-- page-help:production-line -->
这一页同时看所有设备，用来巡线。标题旁是设备台数。右上是当前班次名和时间段。每张卡片上的产量和 OEE 是那一台自己的当班数。上面四个状态数按全部设备计，下面的筛选不会改它们。

### 上面一排

- 目标产能（件/小时）填一个数，再点「应用到全部设备」。确认之后写入每一台的额定产能。各台原来的额定不一样时，输入框是 0。

- 「全部清零」向每台设备写 OEE 清零，并清掉软件侧累计。要先确认，不能撤销。PLC 没连上，或当前账号不是工程师及以上时，这个按钮不可用。

首页只跟顶栏那一台。这里用来先找到要处理的那一台，再进详情。要查一段时间的记录，用历史查询。

打开左侧的产线总览图标，可以按产线布局查看多台设备。

1. 先看整条产线是否存在红色报警或无数据（灰色）设备。

4. 处理现场问题后，等待下一轮采集确认状态恢复。

## 7. 报警中心：发现报警后的正确处理方式

![报警中心](screenshots/03_alarm_center.png)

<!-- page-help:alarm-center -->
左边是还要处理的报警，右边是已经发生过的记录。一条报警恢复之后会离开左边，但右边和历史查询里仍然能查到。标题下的小字是最近一次刷新时间。范围那一排下面还有一句固定说明：事件流和 Top 排行跟所选范围走，今日触发和今日恢复始终从今天 0:00 起。

### 顶栏每个控件管什么

- 设备：一台，或「全部设备」。
- 搜索：按设备名或报警名称过滤。它同时作用在左边列表、今日两个数、最早报警和影响设备上。
- 范围：近 1 小时、近 4 小时、近 24 小时、本班次。打开这一页时默认停在近 4 小时。范围只改变右边的事件流、Top 排行，以及「最频繁」那一格。不改变今日触发和今日恢复。
- 高级、中级、低级：在左边列表标题旁。关掉某一级后，这一级不再出现在左边，今日触发、今日恢复、最早报警、影响设备也会把这一级排除。
- 喇叭：只关本机新报警提示音。列表、颜色和历史记录都还在。整个软件的声音也可以在系统设置的显示里关。
- 刷新：立刻重取。不等的话，左边大约每 3 秒更新，上面的统计大约每 60 秒更新。

### 上面六个数，口径不一样

- 活跃报警：此刻还没恢复、并且通过了设备、搜索和级别筛选的条数。
- 今日触发、今日恢复：从今天 0:00 到现在的事件条数。数字下面的小字是和昨天同一时刻之前那段的对比：▲ 是比昨天多，▼ 是比昨天少。触发变少时小字偏绿，恢复变多时小字偏绿。昨天同期是 0 时，对比显示「—」，因为没法算百分比。鼠标放上去会看到「较昨日同期：昨日 … / 今日 …」。不受「范围」影响，受设备、搜索和级别影响。
- 最早报警·已持续：当前还亮着的里面，开始时间最早的那一条持续了多久，下面一行是它的名称。不是「历史上持续最久的那条」。
- 影响设备：这些活跃报警落在几台设备上。选了单台设备时，这里通常是 1 或 0。
- 最频繁：标签会写成「最频繁报警（近 4 小时）」这一类，括号里就是当前范围。显示的是该范围内触发次数第一的名称。和「今日」不是同一段。范围内没有触发时这里是「—」。

统计读历史库失败时，六个数下面会出现一条红底提示。这时今日对比和最频繁不要拿来下结论，先看运行监控里的采集和数据库。

### 左边每一条长什么样

标题是「实时活跃报警」，左侧有一条红色边。每一条包括报警名称、级别色标（高、中、低）、开始时间、设备名，以及右侧已经持续的时长。同一级别里，开始得更早的靠前。

- 复制：把这条报警的文字复制出去。
- 查看报警历史：跳到历史查询的报警记录，并按这条报警的名称打开。
- 列表最多展示前 200 条，超出时标题旁提示「仅显示前 200 条」。条数为 0 只说明现在没有待处理的，不说明今天没发生过。

处理顺序是先高等级，到现场按名称和设备确认，等 PLC 信号落下后，这条才会从左边消失。若一直不消失，到现场确认信号是否已经落下，再看 PLC 是否连接，以及设备管理里这条报警的地址和名称是否和现场一致。报警管理里没有单独的启用开关，地址填了并保存就会参与采集。不要为了让列表变空而去删记录。

### 右边两块

- 最近事件流：所选范围内的触发和恢复。触发是铃铛图标，恢复是绿色的勾。标题旁写「共 N 件」。同一条报警在两分钟内反复升起时会并成一条，并注明合并了多少次，避免刷屏。列表最多 500 条，超出时提示「仅显示前 500 条」。
- 触发次数 Top 10：同一范围内的排行，最多 10 名。可以改成「按触发次数」或「按持续时长」。按持续时长时，加总的是这一段里各次持续之和：已经恢复的按配对时长，还没恢复的计到现在。它不是「单次最长的那一次」。

比这个范围更早、或要看持续时间和待恢复的完整表，用历史查询的「报警记录」页签。
<!-- /page-help -->

报警中心显示当前活跃报警、今日触发次数、今日恢复次数和最近事件。

### 7.1 处理一条报警

1. 点击左侧导航栏的铃铛图标。
2. 查看“实时活跃报警”列表。
3. 先处理高等级报警，再处理低等级报警。
4. 根据报警名称和设备名称到现场确认原因。
5. 处理现场故障后，等待 PLC 信号恢复。
6. 确认报警从活跃列表消失或状态变为已恢复。
7. 如需追溯，进入历史查询查看发生和恢复时间。

### 7.2 报警颜色和状态

- **红色**：需要优先关注的报警或严重状态。
- **黄色**：需要注意或等待处理的状态。
- **绿色/已恢复**：报警条件已经消失，但历史记录仍会保留。
- **活跃报警数量为 0**：当前没有活跃报警，不代表今天没有发生过报警。

### 7.3 报警一直不消失怎么办

按顺序检查：

1. 现场设备是否真的恢复。
2. PLC 连接是否正常。
3. 报警地址是否配置正确。
4. 设备管理中的报警点是否启用。
5. 报警是否属于需要人工确认的现场条件。

报警中心和首页默认使用视觉提醒；如果现场电脑开启了声音，新的报警还会播放本机提示音。声音可在“系统设置 → 显示设置”中关闭，关闭声音不会关闭报警记录或视觉提醒。

不要直接删除报警记录。删除记录会影响追溯和统计。

## 8. 设备管理：添加和配置设备

![设备管理](screenshots/04_device_manager.png)

<!-- page-help:device-manager -->
这一页改设备配置，需要工程师或管理员账号。左边选设备，右边改。改完必须点「保存」，或按 Ctrl+S。标题旁出现「● 未保存」时，这次修改还没生效。

### 左边

- 搜索和状态下拉只改列表里看得到哪些设备，不改配置。一台都没有时显示「暂无设备」。筛选后没有结果时，可以清除筛选。
- 「新增」加一台。「删除」去掉这台设备的配置，不删除已经写入的产量和报警历史。删之前会确认。
- 「设备校验」检查全部设备，不写入。地址冲突时，标题旁会出现警示图标。
- 导入、导出是设备配置文件，用来备份或换到另一台电脑，不是产量和报警历史。

### 右边六个页签

没选设备时，右边提示先选择一台或点新增。

- 设备参数：设备名称、目标产能（件/小时）、OK 数量地址、NG 数量地址、状态地址、OEE 清零地址、配方名称和配方地址。地址按现场 PLC 程序填，例如 D100。「读取」从 PLC 读当前值，PLC 断开时不可用。产线上的「应用到全部设备」改的也是这里的目标产能。
- 报警管理：每一条要有报警名称、PLC 地址（例如 M100）和报警级别，还可以填英文、日文、葡萄牙文名称。没有单独的启用开关，保存后首页和报警中心就会按这个点报。报警一直不消失时，先核对这里的地址和名称。
- 缺陷管理：缺陷名称和 PLC 地址。首页帕累托写「未配置缺陷项」时，就是这里还没填。
- 计数器报警：报警名称、PLC 地址（例如 D300）、阈值上限、单位。计数达到阈值才触发，和报警管理里的位地址不是同一种点。没配时这一页写「未配置」。
- 数据采集源：这台设备要额外采集的量。设备详情里的数据源卡片来自这里。
- 工单：看这台设备关联的工单。开始和完成仍到工单管理去做。

### 改完之后

保存后等一轮采集。地址改错时，到运行监控看「最近成功读取」会不会掉到 0，以及有没有地址无效或地址冲突。名称改了之后，首页、报警中心和历史查询会显示新名称。旧记录上已经写下的名字不会被改写。
<!-- /page-help -->

设备管理页面分为设备列表和设备详情两部分。左侧选择设备，右侧编辑配置。

### 8.1 添加设备的准备信息

添加设备前准备以下信息：

| 信息 | 示例 | 说明 |
| --- | --- | --- |
| 设备名称 | 注塑机 1 | 页面上显示的名称 |
| OK 计数地址 | D100 | 良品计数器地址 |
| NG 计数地址 | D110 | 不良品计数器地址 |
| 状态地址 | D120 | 设备状态或状态计数地址 |
| 复位地址 | M100 | 班次切换时使用的复位地址 |
| 报警地址 | M200 | 一个报警点对应一个 PLC 位地址 |
| 缺陷地址 | D300 | 缺陷或不良类型对应的计数地址 |

实际地址必须以现场 PLC 程序和设备管理员提供的地址表为准。

### 8.2 添加设备

1. 进入“设备管理”。
2. 点击“新增设备”或页面上的新增按钮。
3. 填写设备名称。
4. 填写 OK、NG、状态和复位地址。
5. 在报警、缺陷或计数报警标签页中添加需要监控的项目。
6. 检查地址是否重复、是否为空、格式是否正确。
7. 点击保存。
8. 返回设备列表，确认设备出现。
9. 等待一次采集周期，确认设备状态和数据开始变化。

### 8.3 修改设备

1. 在左侧设备列表中点击目标设备。
2. 修改需要调整的字段。
3. 点击保存。
4. 如果修改了 PLC 地址，必须观察一次采集结果。
5. 如果修改了设备名称，检查首页、报警中心和历史查询中的显示是否符合预期。

### 8.4 删除设备前的注意事项

删除设备前必须确认：

- 设备已经停止采集或不再使用。
- 不需要继续查询该设备的历史数据。
- 已备份设备配置。

删除设备配置不等于删除历史数据库记录。历史数据是否保留应由管理员按现场数据管理制度决定。

## 9. 历史查询：查生产、报警和状态

![历史查询](screenshots/05_history_query.png)

<!-- page-help:history -->
这一页回看已经写入的记录，不是首页那种此刻画面。改设备、快捷时间、开始、结束、班次或报警类型后，大约等 0.8 秒会自己查一次。也可以直接点「查询」，它马上从第 1 页查起。开始晚于结束时，页面提示「起始时间不能晚于结束时间」，这次不会出结果。

产量、状态、报警的表格每页 50 条，按时间从新到旧。上面的汇总、提示和图按全部命中记录算，翻页只换表里那 50 行。OEE 分析不分页。没有先选出一台设备时，这几个页签都是空的。

### 筛选怎么叠在一起

- 设备：选一台，产量、状态、报警、OEE 都只看这台。报警类型那个下拉只在报警记录页签出现。
- 快捷时间：自定义、今天、昨天、近 7 天、近 30 天。选了今天或昨天之后再去改时刻，快捷项会回到自定义，避免下拉还写着「今天」、时间却已经不是今天。开始和结束两个时刻都包含在内。结束时间若在未来，待恢复的时长和 OEE 用的状态时长会截到现在，不会把还没到来的时间算进去。报警表里还没恢复的触发，持续时间仍是「—」。
- 班次：留在全部就是这段时间里的每个班。选了一个班之后，只保留写入当时记着这个班次名的行。后来改了班次配置，不会改写旧记录上的班次名。
- 报警类型：名单来自这次时间窗口里出现过的报警名称，按名称排序，第一项是全部报警。选中某一项后，表格、四个汇总数和柱图只留这个名称；下拉框本身仍保留其他名称，所以换一项不用先回到全部。
- 「重置」会清掉设备、班次和报警类型，时间改成昨天 0:00 到今天 23:59:59，当前表格先清空。设备空着时，随后的自动查询仍然是空的。
- 查不到时先看时间有没有反了、设备是不是另一台、班次名是不是当时的名字，再到运行监控看那段时间有没有在采集。空结果不等于现场没生产。

### 导出

点「导出」会先问范围。「是」导出全部筛选结果，「否」只导出当前这一页 50 条。文件是带表头的 CSV，写到本机数据目录的 Exports 文件夹里。只导当前页时，文件名会带上页码，文件末尾也会注明这是一页。没有查到记录时导出按钮不可用。SN 追溯不走这个导出。

### 产量查询

上面五个数：总产量、总 OK、总 NG、良品率、不良率，都保留一位小数的百分比。良品率 = 合格数 ÷（合格数 + 不良数）。良品率的颜色和首页不一样：90% 及以上偏绿，70% 及以上偏黄，再低偏红。不良率是其余部分，3% 及以上偏黄，5% 及以上偏红，低于 3% 偏绿。

有数据时，五个数下面有一行提示，再下面是产量图，然后才是表。表的列是时间、设备、班次、OK 产量、NG 产量、当时的设备状态。一行是一条产量记录，不是当前计数器的读数。

### 状态时长

上面四个时长：运行、报警、待机、离线。下面一行提示会写出最长的一段运行、最长的一段待机，以及单次超过 30 分钟的报警。待机占整段查询时间超过 20% 时会单独点出；待机没到这个比例、但报警占整段查询超过 20% 时，才会改点报警占比。

中间三张图从左到右：状态分布、时长柱状图、状态切换时间线。最下面的表是每一次变化，每页 50 条，列是时间、设备、之前状态、之后状态。离线会带原因，例如通讯中断或采集空窗。

### 报警记录：一行是一次边沿

表的列是时间、设备、报警名称、PLC 地址、事件类型、持续时间。事件类型有三种。

- 触发：报警升起。整行浅红。
- 恢复：报警落下。
- 班次切换：跨班时这条报警还没落下，新班次重新开始计时。它不是恢复，也不算进恢复次数。

持续时间只回填在已经配上恢复的那条触发行上。配对办法：每一条恢复，去找同一设备、同一报警、时间更早、还没被别人配走的最近一条触发。恢复行、班次切换、以及窗口里还没等到恢复的触发，这一列都是「—」。

上面四个数按筛选后的全部行计算，翻页不改它们。

- 触发次数、恢复次数：两种事件各有多少条。一次升起加一次落下通常是两行，所以这两个数常常接近，但不会总是相等。
- 待恢复：按「设备 + 报警」分组，窗口里最后一条仍是触发的组数。最后一条若是班次切换，这一组不算待恢复。
- 平均恢复耗时：上面那些已经配上对的时长的平均。满 1 小时显示成小时，否则是整分钟。一条都配不上时这张卡不出现。
- 柱图：按报警名称的触发次数排行。有数据时，图上方的提示会写三件事：触发最多的前几名和占比；5 分钟内先后出现、并且同样的组合至少出现 2 次的连锁；到查询截止时刻仍未恢复、持续最久的前几条。这几条「仍未恢复」看的是后面有没有恢复事件，中间夹了班次切换也仍然算未恢复。它和上面「待恢复」那一格的分组规则不完全相同。

输入序列号后查询这一件留下的记录。表的列是 SN、设备、工单、班次、时间、结果。结果 OK 为绿色，NG 为红色。当前没有启用 SN 记录，或远程连接没有这条通道时，页签只显示当前运行模式不支持 SN 追溯，这时改时间也查不到。

切到这一页签时，设备、起止时间和班次仍用本页上方那一排，改它们会重新算。这一页不分页，也没有报警类型。综合 OEE 是三项相乘，不是平均，所以其中一项很低时，综合值会被拉得更低。四个数都保留一位小数。鼠标放在数字上可以看到这次查询代入后的算式。

### 四个数分别是什么，颜色也不一样

从左到右：良品率、性能达标率、时间稼动率、综合 OEE。

- 良品率 = 合格数 ÷（合格数 + 不良数）。颜色和首页良率相同：95% 及以上偏绿，90% 及以上偏黄，再低偏红。黄表示还没到 95%，但已经接近。这段时间没有产量时是 0，不是「还没算」。
- 性能达标率 = 实际总产量（合格 + 不良）÷（目标产能 × 运行小时）。目标产能的单位是件/小时，只拿运行时间来乘，待机和离线不算进分母。跑得比额定快时，最高显示 100%。没有运行时间或没有目标产能时是 0。颜色按 OEE 档：85% 及以上偏绿，60% 及以上偏黄，再低偏红。
- 时间稼动率 = 运行时间 ÷（运行时间 + 报警时间）。待机、离线都不进分母。因此整班大部分时间在待机、只要报警时间为 0，这项可以是 100%；反过来，运行和报警都没有时，这项是 0。颜色同样是 85% / 60% 两档。
- 综合 OEE = 时间稼动率 × 性能达标率 × 良品率。颜色也是 85% 及以上偏绿，60% 及以上偏黄，再低偏红。

### 三张图、提示，然后才是原料数

从左到右：OEE 指标（三项和综合放在一起）、趋势变化（每个班次一个点，横轴是班次开始时刻，纵轴是该班综合 OEE）、班次对比（每个班一根柱，柱高也是综合 OEE）。

图下面有一行灯泡提示，三项都是 0 时不出现。最低的那一项低于 60% 时，它会点出这是瓶颈。查询里至少有两个班、而且最好的班和最差的班相差达到 10 个百分点时，还会点出落后的那个班，以及三项里拉开差距最大的那一项。相差不到 10 个百分点就不写班次对比。

再下面四个小数字：合格数、不良数、运行时长（小时）、目标产能（件/小时）。这四个是上面公式的原料。对不上百分比时，先看这四个，而不是先怀疑综合值。

### 班次表

最下面的表每一行一个班，列是班次开始、班次、良品率、性能达标率、时间稼动率、OEE。性能达标率低于 60% 的行整行标黄，用来把「跑得慢的班」从「质量差的班」里分开。黄行看的是性能，不是综合 OEE。

某一项明显偏低时：良品率去产量查询看 OK 和 NG；时间稼动率去状态时长看运行和报警各有多久；性能达标率对一下目标产能和运行小时。不要只盯综合百分比。

## 11. 工单管理

![工单管理](screenshots/07_work_order.png)

<!-- page-help:work-orders -->
左边是工单列表，右边是选中这一张的产量和计划。首页中间那张「当前生产进度」只认这台设备上正在进行的那一张。没有进行中的工单，首页那张卡就是空的。

### 一张工单怎么走

- 新增时填写工单号、产品、目标数量、设备和计划开始、计划结束。保存后是待开始。
- 「开始」只对待开始的工单可用。同一台设备上已经有一张进行中时，不能再开始第二张，页面会提示该设备已有进行中工单。
- 「完成」只对进行中的工单可用。完成时把当时的合格数和不良数记在这张工单上，然后弹出「工单已完成」。可以接着开始一张待开始的、空白新建并开始、复制这一张并开始，或稍后再说。
- 「中止」对待开始和进行中都可用，会先确认。进行中被中止时，也会把当时的产量记下。已完成或已中止不能再中止，中止后也不能改回进行中。
- 已完成、已中止之后，列表上的产量用完成或中止时记下的数，不再跟着后来的采集变。

### 列表上的字

- 搜索工单号、产品或设备。旁边的设备下拉只留这一台。状态芯片是全部、待开始、进行中、已完成、已中止，旁边的数字是这一类有多少张。
- 每一行是工单号、产品、达成率和状态。达成率 = 合格数 ÷ 目标数量。合格数不会一直自动刷新，要点「刷新产量」或按 F5，列表上的达成率才会按最新采集重算。
- 「冲突」：同一台设备上，待开始或进行中的工单，计划时间叠在一起。先改计划再开始。
- 「逾期」：计划结束已经过去，工单还没完成。
- 「工单排程排序」默认按计划开始时间。还可以改成计划结束时间、状态 + 计划时间、创建时间。同一排还能只看「仅超期」「仅达标」「有 NG」。导入一次放入多张待开始的工单。「生成样本」要密码确认，只用来预览。
- 一张都没有时提示去点「新增」。筛选后没有结果时写「未找到匹配的工单」。
- 右边没选中时写「请选择工单」。选中后能看到模具/机型、完成进度、良品 / 不良、预计剩余、预计完成、关联设备、创建时间和最近状态变更。

### 不要和当班产量混

工单合格数按这张工单关联的产量记录累加，会跨过班次。首页「当班良品数」只计当前班次，所以两个数可以不一样。删除只去掉这张工单，不删除产量历史。删之前会再确认一次。

常用流程：

1. 点击新增工单。
2. 填写工单号、产品、目标数量、设备和计划时间。

### 保存时会问的几件事

- 改了 PLC、数据来源或运行模式，保存前会再确认一次。PLC 的 IP 或端口变了，会断开当前连接，下一轮采集用新地址重连。「测试连接」只用当前 IP 和端口试一次，不打断正在跑的采集。
- 数据来源在「本地采集」和「远程采集」之间切换后，必须重启才生效。保存完程序会问要不要马上重启。远程模式要填采集服务地址，可先点「测试采集服务连接」。选了远程之后，「PLC 连接」和「采集策略」两个页签会收起来，连接由采集服务负责。
- 班次改了再保存，会提示新配置马上生效。若正处在班次进行中，可能被判成一次切换，并清零当前累计。至少要留一个班次。
- 语言改了要重启界面才换字。字号三档在显示设置里，保存后用于这块屏幕。

### 五个页签

- 通用设置：本地采集是这台电脑自己连 PLC。远程采集是来看 Kanban.Collector，多块屏共用同一份数。运行模式里，完整模式保留管理页面。展示模式只留主页、产线总览、报警中心、设备详情和数据监控，退出时要再确认。保存后侧边栏按新模式收起或放开。
- 显示设置：看板标题、界面语言、字号、新报警声音、过道电视轮播、自动生成单设备日报 PDF。语言是简体中文、English、日本語、Português，改完要重启才换字。字号三档是标准 100%、大屏 115%、超大屏 130%。轮播默认开着，顺序是首页 40 秒、产线 30 秒、报警 20 秒，没有报警就跳过。点一下暂停 16 秒。出现 High 报警时停在报警页。完整模式可以取消轮播。日报按设定时刻，为有数据的每台设备生成上一自然日 PDF，文件在 Reports 目录。多屏时只在一台勾选「日报主节点」，避免每台电脑各出一份。
- PLC 连接：品牌、IP、端口、超时，以及该品牌的协议参数。端口还停在上一品牌的默认值时，换品牌会带出新的默认端口：三菱 4999、西门子 102、Modbus TCP 502、欧姆龙 9600、基恩士 5000。已经改过的端口会保留。

- 班次配置：名称、开始和结束。跨过午夜的班，结束时间落在第二天。首页、报警和 OEE 的「当班」都按这里切。至少留一个班次。班次名一旦写进历史记录，后来改名不会改写旧记录上的名字。

- **本机采集（Local，默认）**：Kanban 直接连接 PLC 采集数据，适合单机部署。
- **采集服务（Remote）**：Kanban 作为显示端连接 Kanban.Collector 采集服务获取数据，适合多屏或远程部署。

选择“采集服务”后需填写**采集服务地址**（默认 `http://127.0.0.1:5129/hubs/kanban`），并可点击“测试连接”验证地址是否可用。

### 12.2 PLC 连接配置（仅本机采集模式）

- **PLC 品牌**：三菱 / 西门子 / Modbus TCP / 欧姆龙 / 基恩士。品牌决定地址格式和默认端口，例如三菱默认 `4999`、西门子默认 `102`、Modbus TCP 默认 `502`。
- **IP 地址**：PLC 的局域网地址，例如 `192.168.1.10`。
- **端口**：由现场 PLC 通信配置确定；切换品牌后会自动带出默认端口。
- **超时（毫秒）**：连接与读写超时时间。

西门子、Modbus TCP、欧姆龙等品牌还有各自的协议参数（型号、机架槽位、站号等），默认值通常可直接使用。

修改 PLC 连接参数后：

1. 检查数字没有填成 0 或负数。
2. 点击保存。
3. 等待连接状态更新。
4. 打开运行监控确认采集周期正常。

### 12.3 采集策略（仅本机采集模式）

- **轮询间隔（毫秒）**：系统读取设备的时间间隔。
- **历史写入间隔（扫描次数）**：每多少次扫描写入一次历史快照。
- **主页刷新间隔（毫秒）**：首页显示刷新间隔。
- 批量读取参数一般无需修改。

轮询间隔过小可能增加 PLC 和电脑负载；历史写入过于频繁可能增加数据库写入压力。没有明确需求时不要随意调整。

### 12.4 班次配置

班次用于统计产量、报警和 OEE 时间：

1. 在系统设置页找到班次配置。
2. 填写班次名称。
3. 设置开始和结束时间。
4. 跨午夜班次要确认结束时间属于第二天的逻辑范围。
5. 保存后，等到下一次采集或重新启动验证。

班次名称一旦用于历史统计，建议不要频繁修改。

### 12.5 界面显示设置

- 暗色主题。
- 界面字号缩放（大屏远距可读性）。
- 看板标题。
- 新报警声音开关。
- **自动生成日报**：勾选后每天在指定时刻自动生成上一自然日生产日报 PDF；多屏部署时“主节点”用于指定由哪台电脑生成，单机部署保持勾选即可。

大屏距离较远时可以提高字号缩放；普通办公显示器建议先使用默认值。

### 12.6 界面语言

在 **系统设置 → 显示设置** 中选择界面语言（简体中文 / English / 日本語 / Português）。语言在**重启程序后**生效。

### 12.7 运行模式（通用设置）

切换运行模式后建议重启程序生效。

## 14. 运行监控：判断系统是否健康

![运行监控](screenshots/09_runtime_monitoring.png)

<!-- page-help:runtime-monitor -->
这一页看采集是否还在跑，不看产量。首页数字长时间不变时，先到这里。页面大约每 1 秒自己刷新。要盯住一个数时，点「暂停刷新」，读完再点「继续刷新」。F5 或右上角「刷新」立刻重取一次。「复制诊断」和「导出诊断」把当前这些数带走，比截图完整。

### 先看哪四格

- PLC 连接：本机采集时，没连上才会出现「重试连接」。看的是远程采集服务时，这个按钮不出现，连接由服务自己重连；连不上时这里写「采集服务不可达」。
- 系统健康：没连上是「通信中断」，采集停了是「采集已停止」，上一轮成功是「运行正常」，上一轮失败是「连续失败 N 次」。
- 最近采集周期：这一轮花了多久。
- 累计断线：连通过程里断过多少次。它不是「现在断了多久」。

### 红底的采集异常

出现「采集异常」时，先读下面那句失败原因。已经连上时，右边是连续失败次数。已经断开时，右边改成断线持续了多久。刚断开时连续失败往往还是 0，所以断开之后不要拿那个次数判断「还没失败」。刷新本身失败时，还会多一行「刷新失败」，这时页面上的数已经停了。

再往下按块看：

- 采集循环：完成轮询、平均周期、最大周期、配置的轮询间隔。实际周期含 PLC 读取耗时和等待。最大周期一直大于配置间隔时，看 PLC 响应、网络，或地址是不是太多。
- 设备读取：「最近成功时间」还在往前走，并且「最近成功读取」大于 0，说明这一轮还能读到设备。长时间是 0，先看 PLC 是否连接、设备管理里的地址是否填了。0 台也会参与断线判定。旁边能看到配置设备数、读取点数和最近成功的设备。
- 采集质量：轮询成功率在还没完成过一轮时显示暂无，不是 0%。P95 周期、P99 周期是最近这些周期里偏慢的那一档。
- 历史写入健康度：最近成功写入、写入失败次数、数据库存储。首页还能看到数、这里写入失败却在涨，这些数就不会进历史查询。
- 系统资源与数据一致性：CPU、内存、磁盘剩余，以及地址冲突、无效地址。
- 设备级采集状态是每一台的读取结果。轮询周期趋势是最近 60 次刷新，单位毫秒。

数字不动时不要删数据库。先确认 PLC 连接、最近成功时间、历史写入这三处。
<!-- /page-help -->

打开监控图标查看系统运行诊断。重点关注：

| 项目 | 正常表现 | 异常表现 |
| --- | --- | --- |
| PLC 连接 | 已连接 | 未连接、反复重连 |
| 采集服务 | 正在运行 | 已停止 |
| 最近成功设备数 | 大于 0 或当前确实无设备 | 长时间为 0 |
| 最近采集时间 | 持续更新 | 长时间不变 |
| 连续失败周期 | 0 或偶尔增加 | 持续增加 |
| 历史写入 | 数据库正常 | 写入错误或磁盘不足 |
| 系统资源 | 内存和磁盘充足 | 内存高、磁盘接近满 |

判断“系统故障”时，至少同时检查 PLC 状态、最近成功采集时间和连续失败周期三个指标。

## 15. 数据监控：查看数据源实时值

![数据监控](screenshots/10_data_monitoring.png)

<!-- page-help:data-source -->
这一页只看各设备数据源的实时采样，不改配置。地址、上下限和触发点在设备管理的「数据采集源」里改。页面大约每 1 秒自己刷新，右上角「刷新」立刻重取一次。

### 上面六个数

总值项、报警、读取失败、过期、未采样、正常。这六个数是全部数据源的合计。下面的设备筛选、状态筛选和搜索只改列表里看得到哪些行。

### 状态怎么读

- 未采样：还没有发起过读取。
- 读取失败：读过，但这次值无效。
- 报警：当前值触发了这条数据源的告警条件。
- 过期：周期采集的点，上次成功已经超过 5 秒。触发式的点不按这 5 秒算过期。还新鲜时，详情里的新鲜度写「新鲜」。
- 正常：读到了，没有告警，也没有过期。

点「异常」只留下不正常的行。「清除筛选」回到全部。搜索匹配设备、数据源、值名称、当前值和地址。

### 三种看法

- 表格：一行一个值，列有设备、数据源、值、类型、当前值、单位、地址、状态、最后更新。
- 紧凑卡片：同一批数收成卡片。
- 趋势图：数值、开关和枚举可以画最近的变化。字符串没有曲线，留在表格里看。

选中一行后，右侧详情给出设备、数据源、当前值、上次有效值、状态、新鲜度、最后更新、判定条件、地址、采集模式、触发地址、触发值和确认值。最后更新写到秒；还没采过时写「未采样」。值长期不动时，先看这一行是读取失败还是未采样，再去运行监控看 PLC 是否还连着。
<!-- /page-help -->

“数据监控”页面展示各设备配置的数据源及其采样值，适合工程师排查地址映射、上下限告警和触发逻辑是否正确。

常用操作：

1. 在设备列表中选择目标设备。
2. 查看各数据源的最近采样值、质量和更新时间。
3. 对比 PLC 实际值，确认地址与数据类型配置无误。
4. 若值长期不更新，先检查 PLC 连接与运行监控中的采集状态。

此页面为只读监控，修改配置需进入“设备管理”。

## 16. 配方管理

![配方管理](screenshots/11_recipe_manager.png)

<!-- page-help:recipes -->
这一页维护要写进 PLC 的配方，需要工程师或管理员。左边是配方列表，右边是编辑。下发用的是已经保存的配方，右边改过的草稿不会直接写进 PLC。

- 右边填配方名称、机型、备注，以及每一行的参数名称、PLC 地址、类型、参数值、下限、上限、单位。至少要有一行参数才能保存。同一机型里配方名不能重复。校验列会标出这一行的问题，校验不过就不会写入。

- 「新建配方」从空白开始。「复制配方」按当前这一条做一份新的。「删除配方」会确认，删的是配方，不删已经写进 PLC 的当前值。

1. 选择目标设备。

3. 保存后在生产切换时选择对应配方。

## 19. 常见问题

### Q1：打开后 PLC 一直未连接

1. 检查网线和交换机。
2. 在 Windows 中确认电脑可以访问 PLC IP。
3. 检查系统设置页 IP 和端口。
4. 确认 PLC 允许当前电脑连接。
5. 查看运行监控和日志。

### Q2：首页产量不增加

1. 确认设备正在生产。
2. 确认 PLC 已连接。
3. 确认 OK/NG 地址没有填错。
4. 确认设备没有处于班次清零窗口。
5. 检查最近成功采集设备数。

### Q3：首页显示「暂无状态数据」或设备离线，但 PLC 是绿色

PLC 绿色只表示 PLC 连接正常，不代表每台设备地址都正确。请检查该设备的地址配置，并在运行监控中确认该设备已被成功采集。

### Q4：报警中心没有报警，但现场设备报警

检查报警点是否已添加、启用，并确认报警 PLC 地址正确。现场报警信号和系统报警点不是自动匹配的。

### Q5：历史查询没有数据

检查查询时间、设备、班次和历史写入状态。刚发生的数据可能还没有到达下一次历史写入周期。

### Q6：保存后配置似乎没有生效

确认是否点击了保存，并重新打开页面检查。若仍无效，检查配置目录是否有写入权限，以及是否生成了 `.corrupt` 文件。

### Q7：程序无法启动或启动后退出

请保留以下信息并联系管理员：

- 出现的完整提示文字。
- 发生时间。
- 是否刚修改过配置。
- 是否刚更换过 PLC 或电脑网络。
- `%APPDATA%\Kanban`（或自定义数据目录）下最近的日志文件。

不要直接删除配置和数据库文件。删除前先备份整个数据目录。

### 19.1 快速诊断表

| 症状 | 可能原因 | 解决 |
| --- | --- | --- |
| 顶部红色横幅「未连接」 | 网络或 PLC 配置错误 | 检查网线、IP/端口，再看运行监控 |
| 顶部黄色横幅「数据停滞」 | 采集端卡死 | 打开运行监控检查采集服务，必要时重启采集 |
| 首页产量不增加 | 地址错误或设备未生产 | 确认 OK/NG 地址与班次清零窗口 |
| 报警中心无报警，现场在报警 | 报警点未配置或未启用 | 核对报警点地址与启用状态 |
| 历史查询无数据 | 时间段内未采集或筛选错误 | 放宽时间段，检查历史写入状态 |
| 导出 PDF 失败 | 本机缺少中文字体 | 安装系统中文字体后重试 |
| 配置保存后未生效 | 未点保存或权限不足 | 重新保存，检查配置目录写入权限 |

> 详细排查步骤见上文 Q1～Q7。

## 20. 日常关机

1. 确认没有正在执行的生产复位或配置保存操作。
2. 确认工单状态已按现场要求更新。
3. 关闭 Kanban 窗口。
4. 等待程序退出完成，不要立即强制结束进程。
5. 如需备份，复制整个 `%APPDATA%\Kanban` 目录（或自定义数据目录）。

## 21. 新手最重要的三条规则

1. **先看 PLC 连接，再判断数据是否异常。**
2. **先确认地址表，再修改设备配置或执行写入命令。**
3. **先备份数据目录，再删除设备、修改班次或处理配置损坏。**

## 附录 B：工程师与管理员补充

以下内容面向设备工程师和 IT/管理员，产线操作员日常可跳过。

### B.1 数据源 CSV 导入导出

在设备详情的「数据源」标签页，可对当前设备的数据源配置执行 CSV 导入和导出。每行对应一个值项；无值项的数据源导出一行源配置。

- 含数据源名称、类型、触发地址、值项地址、上下限、滞回、延时确认等。
- 导入 **替换** 会清空当前设备数据源后导入；**追加** 按名称合并。
- 导入后须点击 **保存** 才生效。
- 建议始终以程序导出的 CSV 为模板，勿手工改列名。

### B.2 界面语言说明

程序支持简体中文、English、日本語、Português。使用手册目前提供 **中文** 与 **English** 两版；界面语言为 **English** 时按 F1 打开英文手册，其他语言（含日本語、Português）打开中文手册。
